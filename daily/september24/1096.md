# 1096. Brace Expansion II

## Problem Statement

Under the grammar given below, strings can represent a set of lowercase words. Let `R(expr)` denote the set of words the expression represents.

The grammar can best be understood through simple examples:

- Single letters represent a singleton set containing that word.
- `R("a") = {"a"}`
- `R("w") = {"w"}`
- When we take a comma-delimited list of two or more expressions, we take the union of possibilities.
- `R("{a,b,c}") = {"a","b","c"}`
- `R("{{a,b},{b,c}}") = {"a","b","c"}`
- When we concatenate two expressions, we take the set of possible concatenations between two words where the first word comes from the first expression and the second word comes from the second expression.
- `R("{a,b}{c,d}") = {"ac","ad","bc","bd"}`
- `R("a{b,c}{d,e}f{g,h}") = {"abdfg", "abdfh", "abefg", "abefh", "acdfg", "acdfh", "acefg", "acefh"}`

Formally, the three rules for our grammar:

- For every lowercase letter `x`, we have `R(x) = {x}`.
- For expressions `e1, e2, ... , ek` with `k >= 2`, we have `R({e1, e2, ...}) = R(e1) ∪ R(e2) ∪ ...`
- For expressions `e1` and `e2`, we have `R(e1 + e2) = {a + b for (a, b) in R(e1) × R(e2)}`

Given an expression representing a set of words under the given grammar, return the sorted list of words that the expression represents.

## Example 1

```text
Input: expression = "{a,b}{c,{d,e}}"
Output: ["ac","ad","ae","bc","bd","be"]
```

## Example 2

```text
Input: expression = "{{a,z},a{b,c},{ab,z}}"
Output: ["a","ab","ac","z"]
Explanation: Each distinct word is written only once in the final answer.
```

## Key Idea

We can parse the expression recursively:

- A brace group `{ ... }` is a list of alternative products.
- A product is a sequence of atoms concatenated together.
- An atom is either a single letter or another brace group.

This naturally matches the grammar:

- comma separates alternatives
- adjacency represents concatenation
- nested braces create recursive expansion

We build each sub-expression as a `Set<String>` to automatically deduplicate results, then sort the final list lexicographically.

## Java Solution

```java
import java.util.*;

class Solution {
    private final String s;
    private int index;

    public Solution(String expression) {
        this.s = expression;
        this.index = 0;
    }

    public List<String> braceExpansionII(String expression) {
        Set<String> result = parseList();
        List<String> answer = new ArrayList<>(result);
        Collections.sort(answer);
        return answer;
    }

    private Set<String> parseList() {
        Set<String> result = new HashSet<>();

        while (index < s.length()) {
            Set<String> product = new HashSet<>();
            product.add("");

            while (index < s.length() && s.charAt(index) != ',' && s.charAt(index) != '}') {
                Set<String> atom = parseAtom();
                Set<String> next = new HashSet<>();

                for (String prefix : product) {
                    for (String suffix : atom) {
                        next.add(prefix + suffix);
                    }
                }

                product = next;
            }

            result.addAll(product);

            if (index < s.length() && s.charAt(index) == ',') {
                index++;
                continue;
            }

            break;
        }

        return result;
    }

    private Set<String> parseAtom() {
        char ch = s.charAt(index);

        if (ch == '{') {
            index++;
            Set<String> group = parseList();
            if (index < s.length() && s.charAt(index) == '}') {
                index++;
            }
            return group;
        }

        index++;
        return new HashSet<>(Collections.singleton(String.valueOf(ch)));
    }
}
```

## Why This Works

The parser follows the grammar directly:

1. `parseList()` reads a comma-separated sequence of alternatives.
2. `parseAtom()` reads either a literal letter or a nested brace group.
3. Adjacent atoms are concatenated by multiplying every prefix with every suffix.
4. `Set<String>` removes duplicates automatically.
5. Sorting at the end gives the required ordered output.

Because each sub-expression is nested recursively, the algorithm handles arbitrary brace depth while preserving the exact grammar.

## Complexity

Let `m` be the total number of generated strings in the final set.

- Time: roughly `O(m * L)` where `L` is the average string length, plus the cost of recursive parsing
- Space: `O(m * L)` for the set of unique strings

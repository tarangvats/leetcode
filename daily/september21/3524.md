# 3524. Find X Value of Array

## Problem Statement

You are given an array of positive integers `nums` and a positive integer `k`.

You are allowed to perform an operation once on `nums`, where in each operation you can remove any non-overlapping prefix and suffix from `nums` such that the remaining array stays non-empty.

You need to find the `x`-value of `nums`, which is the number of ways to perform this operation so that the product of the remaining elements leaves a remainder of `x` when divided by `k`.

Return an array `result` of size `k` where `result[x]` is the `x`-value of `nums` for `0 <= x < k`.

A prefix is a subarray starting from the beginning of the array. A suffix is a subarray starting from any point and ending at the end of the array.

The prefix and suffix chosen for the operation may be empty.

## Example 1

Input: `nums = [1, 2, 3, 4, 5], k = 3`  
Output: `[9, 2, 4]`

## Example 2

Input: `nums = [1, 2, 4, 8, 16, 32], k = 4`  
Output: `[18, 1, 2, 0]`

## Key Idea

The operation always leaves a contiguous middle segment:

- choose prefix length `i`
- choose suffix length `j`
- remaining segment is `nums[i .. n-j-1]`

So the problem is really: count all valid middle segments whose product modulo `k` is `x`.

The brute-force recursive view is:

- at index `i`, decide whether to keep the current element in the remaining segment or remove it as part of the prefix/suffix
- eventually you reach a valid middle segment and compute its product modulo `k`

This leads to a recursive state that depends on the current index and the current product modulo `k`.

With memoization, we cache states so the same subproblem is not recomputed repeatedly. This converts the exponential recursion tree into a polynomial-size DP over index and remainder states.

## Brute Force Recursion Approach

```java
class Solution {
    public int[] findXSum(int[] nums, int k) {
        int n = nums.length;
        int[] ans = new int[k];

        for (int left = 0; left < n; left++) {
            for (int right = 0; right + left < n; right++) {
                int start = left;
                int end = n - 1 - right;
                long prod = 1;

                for (int i = start; i <= end; i++) {
                    prod = (prod * nums[i]) % k;
                }

                if (prod >= 0) {
                    ans[(int) prod]++;
                }
            }
        }

        return ans;
    }
}
```

This tries every possible prefix/suffix pair, then computes the remaining product. It is correct but not efficient because it repeats a lot of work for overlapping subproblems.

## Memoization / DP Approach

```java
import java.util.Arrays;

class Solution {
    public int[] findXSum(int[] nums, int k) {
        int n = nums.length;
        int[][] memo = new int[n + 1][k];
        for (int i = 0; i <= n; i++) Arrays.fill(memo[i], -1);

        int[] ans = new int[k];

        for (int left = 0; left <= n; left++) {
            for (int right = 0; right <= n - left; right++) {
                int start = left;
                int end = n - 1 - right;
                if (start > end) continue;

                int mod = dfs(nums, start, end, k, memo);
                ans[mod]++;
            }
        }

        return ans;
    }

    private int dfs(int[] nums, int l, int r, int k, int[][] memo) {
        if (l > r) return 1;
        if (memo[l][k] != -1) return memo[l][k];

        int result = (int) ((long) dfs(nums, l + 1, r, k, memo) * nums[l] % k);
        memo[l][k] = result;
        return result;
    }
}
```

The key optimization is that the product of the segment is computed recursively and cached by the segment boundaries. Once a state `(l, r)` is solved, it is reused instead of recomputed.

## Why This Works

For every choice of valid prefix and suffix, the remaining array is uniquely determined by the middle segment.

- The brute-force recursion explores all such choices.
- Memoization ensures each middle segment is solved once and then reused.
- The final result array stores how many valid middle segments produce each remainder modulo `k`.

Thus, `ans[x]` is exactly the count of legal operations whose remaining product is congruent to `x` modulo `k`.

## Complexity

### Brute force recursion
- Time: `O(n^2)` for all valid prefix/suffix pairs
- Space: `O(1)` extra besides recursion stack

### Memoized approach
- Time: `O(n * k)` in the optimized recurrence-based version
- Space: `O(n * k)` for the memo table

The memoized approach is usually preferred because it avoids repeated work and scales much better when the same subproblems appear many times.

# 1621. Number of Sets of K Non-Overlapping Line Segments

## Problem Statement

There are `n` points on a one-dimensional plane. Point `i` has coordinate `i`, for `0 <= i < n`.

Count the number of ways to draw exactly `k` non-overlapping line segments such that:

- Every segment covers at least two points.
- Segment endpoints have integral coordinates.
- The segments do not overlap in their interiors.
- Segments are allowed to share endpoints.
- The segments do not need to cover every point.

Return the answer modulo `1_000_000_007`.

## Example 1

Input: `n = 4`, `k = 2`  
Output: `5`

Explanation: The five possibilities are:

- `(0, 2), (2, 3)`
- `(0, 1), (1, 3)`
- `(0, 1), (2, 3)`
- `(1, 2), (2, 3)`
- `(0, 1), (1, 2)`

## Example 2

Input: `n = 3`, `k = 1`  
Output: `3`

Explanation: The possible segments are `(0, 1)`, `(0, 2)`, and `(1, 2)`.

## Example 3

Input: `n = 30`, `k = 7`  
Output: `796297179`

Explanation: The total number of possibilities is `3,796,297,200`. Taking it modulo `1_000_000_007` gives `796,297,179`.

## Constraints

- `2 <= n <= 1000`
- `1 <= k <= n - 1`

## Key Idea

A useful combinatorial observation is:

`answer = C(n + k - 1, 2k)`

where `C(a, b)` is the binomial coefficient, or the number of ways to choose `b` items from `a` items.

The `2k` chosen values represent the `2k` endpoints of the `k` segments. Allowing segments to share endpoints and allowing unused points introduces `k - 1` additional spaces, which changes the effective number of positions from `n` to `n + k - 1`.

Instead of calculating factorials and modular inverses, compute the binomial coefficient with Pascal's identity:

`C(i, j) = C(i - 1, j - 1) + C(i - 1, j)`

This works directly under the modulo and avoids division.

## Java Solution

```java
class Solution {
    private static final int MOD = 1_000_000_007;

    public int numberOfSets(int n, int k) {
        int rows = n + k - 1;
        int columns = 2 * k;
        long[][] combinations = new long[rows + 1][columns + 1];

        for (int row = 0; row <= rows; row++) {
            combinations[row][0] = 1;
        }

        for (int row = 1; row <= rows; row++) {
            for (int chosen = 1; chosen <= columns && chosen <= row; chosen++) {
                combinations[row][chosen] = (
                        combinations[row - 1][chosen - 1]
                        + combinations[row - 1][chosen]) % MOD;
            }
        }

        return (int) combinations[rows][columns];
    }
}
```

## Complexity

- Time: `O((n + k) * k)`
- Space: `O((n + k) * k)`

## Why This Works

The segment arrangement can be transformed into choosing `2k` ordered endpoints from `n + k - 1` effective positions. This gives the binomial coefficient `C(n + k - 1, 2k)`. Pascal's triangle computes that coefficient by combining smaller valid choices, and applying the modulo at every addition keeps the values within range.

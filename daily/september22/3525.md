# 3525. Find X Value of Array II

## Problem Statement

You are given an array of positive integers `nums`, an integer `k`, and a list of queries.

Each query is `[index, value, start, x]` and performs these steps:

1. Update `nums[index]` to `value`. This update remains for all later queries.
2. Remove the prefix `nums[0..start-1]`.
3. Remove any suffix while keeping the remaining array non-empty.
4. Count the number of possible remaining arrays whose product has remainder `x` modulo `k`.

Return an array containing the answer for every query.

After removing the first `start` elements, every possible remaining array is a non-empty prefix of `nums[start..n-1]`:

```text
nums[start..start], nums[start..start+1], ..., nums[start..n-1]
```

Therefore, each query asks for the number of prefixes beginning at `start` whose product modulo `k` equals `x`.

## Example 1

Input:

```text
nums = [1, 2, 3, 4, 5]
k = 3
queries = [[2, 2, 0, 2], [3, 3, 3, 0], [0, 1, 0, 1]]
```

Output:

```text
[2, 2, 2]
```

## Example 2

Input:

```text
nums = [1, 2, 4, 8, 16, 32]
k = 4
queries = [[0, 2, 0, 2], [0, 2, 0, 1]]
```

Output:

```text
[1, 0]
```

## Key Observation

For a segment, we only need two pieces of information:

1. `product`: the product of every element in the segment modulo `k`.
2. `prefixCount[r]`: the number of non-empty prefixes of the segment whose product has remainder `r` modulo `k`.

A segment tree can store this information for every interval.

This is enough because two adjacent segments can be merged efficiently.

## Merging Two Nodes

Assume a node represents the concatenation of a left segment and a right segment.

### Whole product

```text
parent.product = left.product * right.product % k
```

### Prefixes of the combined segment

Every non-empty prefix of the combined segment is one of two types:

1. It ends inside the left segment.
   - These counts are already stored in `left.prefixCount`.
2. It contains the entire left segment and then ends inside the right segment.
   - If a right prefix has product remainder `r`, its combined product is:

```text
(left.product * r) % k
```

So the merge operation is:

```text
parent.prefixCount = left.prefixCount

for each remainder r:
    combinedRemainder = left.product * r % k
    parent.prefixCount[combinedRemainder] += right.prefixCount[r]
```

Because `k <= 5`, checking every remainder takes constant time.

## Segment Tree Solution

```java
class Solution {
    private static class Node {
        int product;
        int[] prefixCount;

        Node(int k) {
            prefixCount = new int[k];
        }
    }

    private Node[] tree;
    private int[] nums;
    private int k;

    public int[] resultArray(int[] nums, int k, int[][] queries) {
        this.nums = nums;
        this.k = k;

        int n = nums.length;
        tree = new Node[4 * n];
        build(1, 0, n - 1);

        int[] result = new int[queries.length];

        for (int queryIndex = 0; queryIndex < queries.length; queryIndex++) {
            int index = queries[queryIndex][0];
            int value = queries[queryIndex][1];
            int start = queries[queryIndex][2];
            int remainder = queries[queryIndex][3];

            nums[index] = value;
            update(1, 0, n - 1, index);

            Node suffix = query(1, 0, n - 1, start, n - 1);
            result[queryIndex] = suffix.prefixCount[remainder];
        }

        return result;
    }

    private void build(int node, int left, int right) {
        if (left == right) {
            tree[node] = createLeaf(nums[left]);
            return;
        }

        int middle = left + (right - left) / 2;
        build(node * 2, left, middle);
        build(node * 2 + 1, middle + 1, right);
        tree[node] = merge(tree[node * 2], tree[node * 2 + 1]);
    }

    private void update(int node, int left, int right, int index) {
        if (left == right) {
            tree[node] = createLeaf(nums[index]);
            return;
        }

        int middle = left + (right - left) / 2;
        if (index <= middle) {
            update(node * 2, left, middle, index);
        } else {
            update(node * 2 + 1, middle + 1, right, index);
        }

        tree[node] = merge(tree[node * 2], tree[node * 2 + 1]);
    }

    private Node query(int node, int left, int right, int queryLeft, int queryRight) {
        if (queryLeft <= left && right <= queryRight) {
            return tree[node];
        }

        int middle = left + (right - left) / 2;

        if (queryRight <= middle) {
            return query(node * 2, left, middle, queryLeft, queryRight);
        }
        if (queryLeft > middle) {
            return query(node * 2 + 1, middle + 1, right, queryLeft, queryRight);
        }

        Node leftResult = query(node * 2, left, middle, queryLeft, queryRight);
        Node rightResult = query(node * 2 + 1, middle + 1, right, queryLeft, queryRight);
        return merge(leftResult, rightResult);
    }

    private Node createLeaf(int value) {
        Node leaf = new Node(k);
        leaf.product = value % k;
        leaf.prefixCount[leaf.product] = 1;
        return leaf;
    }

    private Node merge(Node left, Node right) {
        Node parent = new Node(k);
        parent.product = (int) ((long) left.product * right.product % k);

        for (int remainder = 0; remainder < k; remainder++) {
            parent.prefixCount[remainder] += left.prefixCount[remainder];

            int combinedRemainder = (int) ((long) left.product * remainder % k);
            parent.prefixCount[combinedRemainder] += right.prefixCount[remainder];
        }

        return parent;
    }
}
```

## Why This Works

A query after removing the first `start` elements can keep any non-empty prefix of the suffix beginning at `start`. The segment tree query returns one combined node for exactly the range `[start, n - 1]`.

The node's `prefixCount[x]` is therefore the number of valid remaining arrays whose product is congruent to `x` modulo `k`.

Point updates only affect the nodes on the path from the changed leaf to the root, so the information stays current for all later queries.

## Complexity

Let `n = nums.length` and `q = queries.length`.

- Building the segment tree: `O(nk)`
- Updating one index: `O(k log n)`
- Querying one suffix: `O(k log n)`
- Total: `O((n + q log n)k)`
- Space: `O(nk)`

Since `k <= 5`, this is effectively `O(n + q log n)`.

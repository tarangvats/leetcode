# 1722. Minimize Hamming Distance After Swap Operations

## Problem Statement

You are given two integer arrays, `source` and `target`, both of length `n`. You are also given `allowedSwaps`, where each pair `[a, b]` means that the elements at indices `a` and `b` in `source` may be swapped.

A swap can be performed multiple times and in any order.

The Hamming distance between two arrays is the number of indices where their values differ. Return the minimum possible Hamming distance between `source` and `target` after performing any number of allowed swaps.

## Example 1

Input: `source = [1, 2, 3, 4]`, `target = [2, 1, 4, 5]`, `allowedSwaps = [[0, 1], [2, 3]]`  
Output: `1`

Explanation:

- Swap indices `0` and `1`: `source = [2, 1, 3, 4]`.
- Swap indices `2` and `3`: `source = [2, 1, 4, 3]`.

The arrays differ only at index `3`, so the minimum Hamming distance is `1`.

## Example 2

Input: `source = [1, 2, 3, 4]`, `target = [1, 3, 2, 4]`, `allowedSwaps = []`  
Output: `2`

Explanation: No swaps are allowed, so indices `1` and `2` remain different.

## Example 3

Input: `source = [5, 1, 2, 4, 3]`, `target = [1, 5, 4, 2, 3]`, `allowedSwaps = [[0, 4], [4, 2], [1, 3], [1, 4]]`  
Output: `0`

## Constraints

- `n == source.length == target.length`
- `1 <= n <= 10^5`
- `1 <= source[i], target[i] <= 10^5`
- `0 <= allowedSwaps.length <= 10^5`
- Each `allowedSwaps[i]` contains two different indices.
- `0 <= a_i, b_i < n`

## Key Idea: Connected Components

Treat every index as a node in a graph. Each allowed swap is an edge between two indices.

If two indices belong to the same connected component, a sequence of allowed swaps can move values between any positions in that component. Therefore, the final arrangement of values inside a component can be any permutation of the original values from that component.

The problem can be solved in three steps:

1. Use a Disjoint Set Union (DSU) structure to find connected components of indices.
2. For each component, count the values available in `source`.
3. Visit the corresponding positions in `target`:
   - If the component contains the required target value, use one copy of it.
   - Otherwise, that position must remain incorrect and increases the answer.

This greedy matching is optimal because every matching value reduces the Hamming distance by one, and values cannot move between different components.

## Java Solution

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

class Solution {
    public int minimumHammingDistance(
            int[] source, int[] target, int[][] allowedSwaps) {
        int n = source.length;
        DSU dsu = new DSU(n);

        for (int[] swap : allowedSwaps) {
            dsu.union(swap[0], swap[1]);
        }

        Map<Integer, List<Integer>> components = new HashMap<>();
        for (int index = 0; index < n; index++) {
            int root = dsu.find(index);
            components.computeIfAbsent(root, key -> new ArrayList<>()).add(index);
        }

        int mismatches = 0;

        for (List<Integer> component : components.values()) {
            Map<Integer, Integer> available = new HashMap<>();

            for (int index : component) {
                available.put(
                        source[index],
                        available.getOrDefault(source[index], 0) + 1);
            }

            for (int index : component) {
                int required = target[index];
                int count = available.getOrDefault(required, 0);

                if (count > 0) {
                    available.put(required, count - 1);
                } else {
                    mismatches++;
                }
            }
        }

        return mismatches;
    }

    private static class DSU {
        private final int[] parent;
        private final int[] rank;

        DSU(int n) {
            parent = new int[n];
            rank = new int[n];

            for (int index = 0; index < n; index++) {
                parent[index] = index;
            }
        }

        int find(int value) {
            if (parent[value] != value) {
                parent[value] = find(parent[value]);
            }
            return parent[value];
        }

        void union(int first, int second) {
            int firstRoot = find(first);
            int secondRoot = find(second);

            if (firstRoot == secondRoot) {
                return;
            }

            if (rank[firstRoot] < rank[secondRoot]) {
                parent[firstRoot] = secondRoot;
            } else if (rank[firstRoot] > rank[secondRoot]) {
                parent[secondRoot] = firstRoot;
            } else {
                parent[secondRoot] = firstRoot;
                rank[firstRoot]++;
            }
        }
    }
}
```

## Complexity

Let `n` be the array length and `m` be the number of allowed swaps.

- Time: `O((n + m) * alpha(n))` amortized, plus expected `O(n)` hash-map work.
- Space: `O(n)`.

Here, `alpha(n)` is the inverse Ackermann function, which is effectively constant for practical input sizes.

## Why This Works

Allowed swaps connect indices into components. Values can be rearranged freely within one component, but cannot cross into another component. Matching as many target values as possible against the multiset of source values in each component maximizes the number of correct positions. The remaining positions are exactly the unavoidable mismatches, so their count is the minimum Hamming distance.
